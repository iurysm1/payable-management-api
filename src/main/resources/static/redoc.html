Criar conta a pagar

Cadastra uma conta para um fornecedor existente. O status padrão é PENDENTE. Uma conta PAGO exige paymentDate e outros status exigem essa data nula.

Authorizations:
basicAuth
Request Body schema: application/json
required

Dados da nova conta a pagar.

amount
required
number >= 0

Valor monetário não negativo, com até duas casas decimais.

description
required
string

Descrição da conta a pagar.

expirationDate
string <date>

Data de vencimento no formato ISO-8601.

paymentDate
string <date>

Data do pagamento, obrigatória somente para status PAGO.

status
string
Enum: "PENDENTE" "PAGO" "CANCELADO"

Status da conta. Quando omitido, assume PENDENTE. PAGO exige paymentDate; os demais status não admitem data de pagamento.

supplierId
required
integer <int64>

Identificador de um fornecedor existente.

Atualiza somente o status. Ao passar para PAGO sem paymentDate, utiliza a data atual ou preserva a data anterior se a conta já estava paga. Outros status removem a data.

required
integer <int64>

Request Body schema: application/json
required

string <date>

Data de pagamento. Ao mudar para PAGO, a data atual é usada quando omitida. Para outro status, a data armazenada é removida.

status
required

Código do status: 0=PENDENTE, 1=PAGO, 2=CANCELADO.

Importar contas por CSV

Recebe um CSV UTF-8, salva o arquivo, cria uma importação PENDING e publica um evento no RabbitMQ. O 201 confirma a aceitação, não o término. O consumidor muda o estado para PROCESSING e depois COMPLETED, COMPLETED_WITH_ERRORS ou FAILED.

Cabeçalho obrigatório: description,amount,status,expirationDate,paymentDate,supplierId. Os status aceitos são PENDENTE, PAGO e CANCELADO; datas usam yyyy-MM-dd. Linhas em branco são ignoradas e campos podem usar aspas duplas.

Authorizations:
basicAuth
Request Body schema: multipart/form-data
required

Arquivo CSV com extensão .csv.

file
required
string <binary>

CSV UTF-8 com cabeçalho obrigatório: description,amount,status,expirationDate,paymentDate,supplierId

Gerar relatório de pagamentos

Consolida as contas com status PAGO cuja paymentDate esteja no período inclusivo. supplierId é opcional; startDate e endDate são obrigatórias e devem formar um período válido.

basicAuth
query Parameters

integer <int64>

Fornecedor opcional para restringir o relatório.

startDate
required
string <date>
Example: startDate=2026-08-01

Data inicial inclusiva no formato ISO-8601.

endDate
required
string <date>
Example: endDate=2026-08-31
